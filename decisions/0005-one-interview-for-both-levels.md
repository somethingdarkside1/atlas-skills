# One interview skill covers both the foggy effort and the single part

Matt's set has `grill-with-docs` for an idea that fits one session and `wayfinder` for an effort too foggy to hold, storing the fog as decision tickets on a tracker. In Atlas the map already holds the fog: a sketched part is an open question. `/interview-me` takes the whole project or one part, and `/atlas` picks the next sketched part. The zoom lives in the map, so one skill is enough. On the whole project it drafts the map from what exists before asking anything, questions the draft breadth-first, and decides nothing; on a part it asks until the open questions are gone and ends by writing the brief.

Considered: a separate charting skill (a ninth command, and the draft split from the questions that give it value); `/map-it` drafting and `/interview-me` questioning (three commands before the first real question).
