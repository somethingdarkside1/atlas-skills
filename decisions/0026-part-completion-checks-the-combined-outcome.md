# A part is done when its combined result meets the brief

When a part's tasks pass review, check the combined result against its brief's Outcome before marking the part done. If the Outcome still promises missing work, retain acceptance of the completed tasks, keep the part open, and identify the missing work for planning; a map redraw cannot infer acceptance from task counts alone. Accepted by Vitali on 2026-09-19 in answer to Q4, using passed logo exports with a missing promised usage guide as the example.

Considered: marking the part done whenever its tasks pass, or rejecting otherwise accepted tasks because the plan omitted work.
Revisit when: a combined result cannot be assessed without a separate integration task, which should then own that check.
