# Atlas owns work and project instructions own delivery

Atlas operations create and assess work, shared methods supply reasoning, and project instructions govern commits, branches, worktrees, pushes, PRs, and merges. This proposed boundary lets acceptance remain stable when a project changes its delivery policy, while the agent can continue an already-authorized delivery step after review.

Considered: keeping Git inside each skill; centralizing Git in the Atlas plan format; removing all workflow awareness.
Revisit when: a concrete project action cannot be represented without changing Atlas acceptance semantics.
