# The interview writes the brief, and the plan holds only tasks

A part is decided when its brief exists, and the interview writes it as its last step, because the interview is the only moment with the context to say what the part must do and why. Settled choices too small for a decision file go into the brief's Decisions section as one line each, so nothing settled lives only in chat. `/plan-it` reads the brief and writes tasks. The earlier design had `/plan-it` write the brief in a later session from the map and the decisions alone, which lost every small choice made in between.

Considered: a `Settled:` line on each map part (turns the map into a spec); the plan skill writing the brief from memory it does not have.
Revisit when: a brief needs input from more than one interview.
