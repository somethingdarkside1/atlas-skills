# 02: Create realistic behavioral fixtures

## Delivers
Verifiable software and non-code fixtures with actual outputs and scripted setup for important lifecycle failures.

Source: Original F28 and the initial review evaluation table. See the [package brief](brief.md) and [architecture review](../../notes/2026-09-13-review-methods-and-project-policy.md).

## Check by
Run the scenarios below against a scratch copy or the exact candidate revision and record the observed outputs, checks, and limits.

## Done when
- [ ] The brand fixture contains the files its completed tasks claim, or accurately marks unfinished work.
- [ ] Fixtures cover brief-only, interrupted, waiting, changes-requested, canceled, stale-review, and changed-scope work.
- [ ] Setup and cleanup keep source fixtures and unrelated user work unchanged.
- [ ] Expected observations test behavior and evidence, not wording compliance.

## Delivered
Pending. Record the selected workspace/branch when work begins, then the output revision and actual check evidence when delivered.

## Review
Pending. Record the reviewed output and brief revision, findings or acceptance, and any unresolved human judgment.
