# Build it

Make the selected result and leave a usable record for review or resumption.

Read the task and latest attempt, brief, relevant decisions, plan working rules and evidence format, project instructions, and existing work of this kind. Inspect the workspace and the actual outputs of required blockers. Use a relevant handoff only for context missing from these records.

1. Select the requested ready task or resume its existing attempt. Read and resolve its pending action using current evidence and answers. If nothing relevant changed and no justified action is available, report the existing wait. A missing blocker output needs access or recovery, even if its task says done. Reuse owned partial work and preserve unrelated edits.
2. Mark the task doing and the part building as appropriate. Make what Delivers names within the current brief. Use the project's methods for this medium. When a failure needs explanation, use [diagnosis](diagnosis.md). For behavioral code changes, favor a small observable failing case and the smallest correction, with refactoring supported by passing checks. A missing material scope decision is recorded once for interview-me; routine implementation judgment does not require a new interview.
3. Run the task's checks and required project checks. Use [verification](verification.md) when selecting or interpreting adequate evidence, especially when a check could pass for a wrong result. Tick only criteria actually established; retain human judgments for the person. Correct a failed result and rerun affected checks when there is a justified next action.
4. Record delivery or the exact stop under the plan evidence format. Identify the actual files or external result and applicable scope, using [evidence.py](evidence.py) for file identities if the project has no equivalent. A complete agent-checkable delivery moves to review, including any remaining human judgment. A stopped attempt remains doing with its workspace, partial result, and pending action. Save owned changes under project policy.

End with the separate review command for a delivery, or the named action/input needed to resume. Build does not invoke review automatically. A delivery failure such as an unavailable remote is recorded separately from the checks on the work itself.
