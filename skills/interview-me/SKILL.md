# Interview me

Resolve enough uncertainty for the selected work to proceed.

Read the target's map section, brief, applicable decisions, and affected task records, plus the relevant home formats and plan working rules. Use existing answers from project records, current conversation, and a relevant handoff. A missing required home routes to setup.

1. Select the part or project from the request. For project discovery, inspect real material and draft a small map of independently understandable outcomes before asking about it. Leave undiscovered scope broad; do not turn every unknown into a task. For a clear request within an adopted brief, use the existing scope and recommend planning or building directly.
2. Use [interviewing](interview.md) to resolve remaining choices. If a reported constraint may be an unexplained failure, use [diagnosis](diagnosis.md) before treating it as a design requirement. Keep unformulated in-scope uncertainty distinct from exclusions and from questions that are already answerable.
3. Persist settled answers before continuing: update the brief's small choices, consequential decisions with actual adoption status, meaningful glossary distinctions, and the map's affected questions and dependencies. A draft brief may exist while the part remains sketched. Each fact has one owner; other homes link to it.
4. When adopted scope changes, preserve the earlier scope and assess affected deliveries, dependencies, and human judgments under the plan format. Update only affected work. If the next answer requires an experiment, leave a bounded question linked for prototype-it. If it requires a human decision, preserve that exact pending question and wait without repeating settled rounds.

Finish when the selected scope is clear enough for its next work or a specific unresolved input has a usable resume action. A settled new part becomes decided; an active part retains its progress except where changed scope invalidates acceptance. Save owned changes under project policy. Recommend the needed planning, prototype, or build action; no blanket restart of the project.
