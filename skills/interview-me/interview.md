# Interviewing

Use when a selected outcome has material uncertainty about scope, meaning, acceptance, or a consequential choice. The caller supplies the target, current brief or request, relevant evidence, prior answers, and the decision needed next. The caller owns project writes and state changes.

1. Separate accessible facts, assumptions, delegated choices, and decisions only the person can make. Investigate accessible facts yourself. Test a disputed description against real examples or existing behavior before asking the person to repeat it. Reuse still-applicable answers and authorization.
2. Ask only questions whose prerequisites are settled. Choose a manageable round based on consequence and dependency, with a recommendation and meaningful tradeoffs where useful. An answer can change which questions matter next; respond to confusion or a question asked back before advancing. Leave dependent questions for later instead of presenting guesses as settled prerequisites.
3. Use concrete cases to sharpen ambiguous concepts: which real example belongs to each meaning, and what would differ if the meaning changed? Propose a project term only when the distinction affects decisions or behavior. Reading known vocabulary needs no separate modeling exercise.
4. Return settled answers as they arrive so the caller can preserve them. A skipped answer is unanswered, unless the person has explicitly delegated that class of choice. Keep consequential choices pending. Stop when the selected next work is clear, an experiment is needed, or a specific required answer is unavailable. Assign later uncertainty a trigger without extending the current interview to every future branch.

Return the settled scope and small choices, proposed or adopted consequential decisions with their authority, useful term distinctions, remaining material questions with who or what can answer them, and the next usable action. An unchanged unresolved question remains one pending item, not a new interview each time.
