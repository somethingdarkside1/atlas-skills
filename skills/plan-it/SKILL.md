# Plan it

Turn adopted scope into work someone can complete and check.

Read the selected brief and decisions, the map's responsibility and decision dependencies, plan working rules and task format, existing tasks in scope, and any cross-part dependencies you will change. If the outcome is materially unresolved, name the missing choice for interview-me; an unrelated later question need not block this plan.

1. Reuse existing tasks and scope. For a clear small request, create or revise one task under the brief. An already adequate plan needs no rewrite. Resolve only consequential uncertainty in the breakdown with [interviewing](interview.md), reusing the user's existing direction rather than asking for another generic confirmation.
2. Shape work into independently verifiable results, sized for a practical attempt. Prefer a complete thin path through a feature or process. For wide mechanical changes, plan compatible expansion, migration batches, and removal; when intermediate results cannot stand alone, explicitly identify the integration task and where combined verification happens. A task can deliver a decision, experiment, document, dataset, design, code, or external action.
3. Write Delivers, Check by, and observable Done when criteria. Identify human-only judgments. Give blockers only to work that actually supplies a required output. Use stable ids and the next unused task number; future discoveries can add tasks without renumbering history.
4. Replan under the plan format's change-impact rules. Preserve existing attempts, evidence, and valid acceptance. Record why work is canceled and repair incoming dependencies. A changed requirement can reopen affected accepted work; unrelated done tasks stay accepted. Repair known missing work under the current brief instead of sending it to an interview when no decision is missing.
5. Check that required outcomes are covered, every blocker exists and is meaningful, dependencies have no cycles, and the next task can access its inputs. Save only the owned plan and any map pointers that changed under project policy.

Finish with the selected task to build, the exact unresolved choice or missing dependency, or a statement that the existing plan already covers the request. Repeating the same request reuses the result.
