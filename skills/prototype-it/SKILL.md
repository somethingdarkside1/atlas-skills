# Prototype it

Make the smallest useful experiment when reading or discussion cannot settle a decision.

Read the selected question, relevant part/brief and prior evidence, the note format, and project working rules. An explicit question may start the experiment before a full plan exists; record its project or part association without requiring an interview just to add a marker.

1. Reuse a relevant existing experiment where possible. Use [prototyping](prototype.md) to identify the deciding observation, appropriate medium, effort bound, and who can judge the answer. Facts available from existing sources need investigation rather than a prototype.
2. Build and observe within the authorized scope. Put the artifact in a clearly named prototype location appropriate to the project, with the question and a simple way to inspect it. Include tests, persistence, or error handling when the question needs them. Stop at an answer, a stated limit, or unavailable deciding evidence.
3. Record observations separately from preferences and assumptions. Return a measured answer with its limits; seek a person's decision where preference or external judgment is required. An inconclusive experiment records the next observation needed, without rerunning itself unchanged.
4. Preserve the artifact and evidence pointer in a distinct dated note. Update only the question's authoritative home, linking the note: the brief or decision for a settled answer, or the pending question for an unresolved one. Evidence links are allowed; any prototype material promoted into real work is verified and reviewed under that work's criteria.

Save owned changes under project policy. Finish with the next decision, task, or explicit wait. The project chooses retention and Git workflow; a prototype need not create a new branch or production dependency.
